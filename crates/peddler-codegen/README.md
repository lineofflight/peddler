# peddler-codegen

`peddler-codegen` generates the API code of the [`peddler` crate](../peddler/README.md), and the Ruby methods that call it, from Amazon's Selling Partner API models.

It is a development tool. It is not published, and neither the gem nor the crate ships it: both build from the generated code that is committed.

Peddler has two generators. This one writes Rust, and the Ruby method of each operation with its documentation and its types. The [Ruby generator](../../lib/generator/README.md) writes the typed Ruby models.

## What it reads

- `selling-partner-api-models/`, a checkout of [Amazon's models][models] at the revision in `selling-partner-api-models.sha`. It reads every API model under `models/` and every report, feed, notification and Data Kiosk schema under `schemas/`, the files the Ruby generator reads. [Names](#names) says how it names them.
- `pagination.json`, which says which operations return pages and how to ask for the next one.
- `lib/generator/patches/`, four JSON patches that repair notification schemas. The Ruby generator applies the same ones.

## What it writes

| Path | Holds |
| --- | --- |
| `crates/peddler/src/apis/<api>/models.rs` | the typed models of an API version |
| `crates/peddler/src/apis/<api>/facade.rs` | for each operation, a parameter struct, an async function and, where it pages, a `*_pages` function |
| `crates/peddler/src/apis/dispatch.rs` | `apis::execute`, which runs an operation by its key with JSON arguments. The Ruby extension calls it |
| `crates/peddler/src/apis/pagination.rs` | the pagination mapping of each paged operation |
| `crates/peddler/src/{reports,feeds,notifications,data_kiosk}/` | the typed models of the other schemas |
| `lib/peddler/native/apis.rb` | the class of each API with the Ruby method of each operation, the method of each API on `Peddler::Client`, the comment above each of them with its types as inline RBS, and the pagination mappings |
| `crates/peddler-codegen/operation-inventory.json` | every operation with its method, path, rate, parameters, responses and pagination, and under `unmapped_pagination` each operation that looks paged and isn't mapped |

Every Rust file starts with `// Generated by peddler-codegen. Do not edit.`, and the Ruby file carries the same line as a `#` comment.

It writes no signature file. `bundle exec rake rbs:export` writes `sig/inline/peddler/native/apis.rbs`, the signatures an application gets, from the types in the Ruby file.

## Running it

You need a stable Rust toolchain, Git, and Ruby with `bundle install` done. Ruby converts the Data Kiosk schemas, with the `graphql` gem.

From the repository root:

```sh
# Check out Amazon's models at the pin, then generate
bundle exec rake generate:rust

# The same, comparing with the files on disk and writing nothing
bundle exec rake generate:rust:verify
```

`bundle exec rake generate` runs this generator, then the Ruby one, then `rbs:export`. `bundle exec rake generate:verify` regenerates everything at the pin and fails if a committed file changes, an exported signature included. `generate:rust` alone doesn't export. `bundle exec rake generate:update` moves the pin to Amazon's latest revision first.

The generator is a Cargo workspace of its own, with its own `Cargo.lock`, so every `cargo` command names its manifest:

```sh
bundle exec rake generate:rust:setup
cargo run --manifest-path crates/peddler-codegen/Cargo.toml --locked -- --root .
cargo run --manifest-path crates/peddler-codegen/Cargo.toml --locked -- --root . --check
cargo test --manifest-path crates/peddler-codegen/Cargo.toml --locked
```

The tests read the pinned checkout, so run the setup task first. `cargo test --workspace` at the repository root doesn't run them: the root workspace holds the crate and the extension only.

| Flag | Meaning |
| --- | --- |
| `--root <path>` | the repository to read from and write to. The default is the one the generator is in |
| `--output-root <path>` | write to, or compare with, another directory |
| `--check` | write nothing, and fail if a generated file is missing, differs or is no longer generated |

## What it guarantees

- It runs only on the pinned revision. The checkout must be at the pin, and the files it reads must be tracked there and unmodified.
- It reads the files the pin tracks, as the Ruby generator finds them. A model or a schema Amazon adds is generated, and one it removes goes, with its files. A file the pin doesn't track fails generation.
- The same input gives the same bytes.
- It writes all or nothing. Every file is generated before any is replaced, or removed for a model or a schema Amazon removed.
- It refuses what it has no rule for, and says where. A refusal names the spec file and the operation, such as `catalog-items-api-model/catalogItems_2022-04-01.json: searchCatalogItems: unsupported default for a body`, or the file alone for a name it can't derive.
- It warns, on stderr, of what it generates without a rule: an operation that looks paged and isn't mapped, and an entry of `pagination.json` for an API Amazon removed.

## Operations

`src/clients.rs` reads each operation of a model: its method and path, its rate, its parameters and their types and defaults, the body, and the model of each successful response. `src/facades.rs` writes the Rust functions and the Ruby methods from that, and `src/docs.rs` the comments above the Ruby ones.

The Rust items carry the spec's text as their docs. A function and an API's module have the text of the Ruby method and class. A field of a parameter struct has the parameter's description and its known values, as a field of a model has.

Every generated doc, a model's too, is written as `///` lines. In it, Amazon's `doc:` links are full URLs, as in Ruby, and a code block is marked `text`, so that `cargo test` doesn't run it as a doctest.

A generated function builds its request itself. It escapes each path parameter as one segment. It joins an array into one comma-separated query parameter, or repeats the parameter where the model says `collectionFormat: multi`. It serializes the body as JSON.

It doesn't check a value against the model's constraints, such as a pattern or a maximum: Amazon does. It keeps the defaults the model declares.

The rate is the requests per second in the usage plan table of an operation's description, the only place a model has it. The generator reads the first row of the table whose header ends with `Rate (requests per second)` and `Burst`, and takes the cell under the first. Every rate it reads is the one Peddler 5 read. A generated function hands the rate to the client with its request, and the client waits by it before it retries a 429. An operation without a usage plan, or with a rate of `n`, which varies by seller, has none.

A description that mentions a usage plan or a burst without such a table fails generation, and so does a rate that is not a positive number. So a change in how Amazon writes the table can't go unnoticed, and neither a rate in another unit nor the burst is taken for the rate.

An operation with one successful response returns `TypedResponse<T>`. One with several returns a type with a decoder for each status, such as `json_200` and `json_202`. One without a model returns the raw `Response`.

A Ruby method takes the required parameters in order and the optional ones as keywords, under the names Peddler 5 used. A keyword of Rust is such a name too: a parameter `type` is `type:` in Ruby and `type_` in Rust. A method or a parameter named after a keyword of Ruby is refused, and so is a method named `initialize`. It passes each argument through `Peddler::Native::Arguments`, which takes the forms Peddler 5 took and names the argument in what it raises.

Each Ruby method and API class has the comment Peddler 5 gave it: the model's description and a note where the operation can run in the sandbox. Under it are the method's types as inline RBS: a `# @rbs` line for each parameter, with the model's description of it and the values its enum lists, and one for what it returns. A `*_pages` method and an API's method on the client have one line of text and their whole type in a `#:` line. The latest version of an API is a method of its own, since Steep reads no alias.

A model's text is data. A line break in it can't end a comment and start code: none gets through the function that writes the comment lines. A line of it that starts with `@rbs` can't pass for an annotation: it is written after a backtick.

## Names

`src/manifest.rs` names each API model as the Ruby generator does, so that both give a model the same name and a new one needs no edit. The Ruby generator fails if they don't: it finds each API in the operation inventory by its name.

- The family is the name of the model's directory, without `-api-model` or `-model`, with underscores: `amazon-warehousing-and-distribution-model` is `amazon_warehousing_and_distribution`. In a directory of `FILENAME_BASED_DIRECTORIES`, which hold several APIs, it is the file's name without its date or `V` and number, in snake case: `finances-api-model/financesInvoices_2026-06-25.json` is `finances_invoices`.
- The version is the model's `info.version`, with underscores, and the module is the family and the version: `finances_invoices_2026_06_25`.
- The latest version of a family is its last dated one, or its last `v` one if none is dated, as Peddler 5 chose: `client.messaging` is `messaging_2026_04_20`, not `messaging_v1`.
- The Ruby class of the module takes Peddler's acronyms: `fba_inventory_v1` is `FBAInventoryV1`.

`FILENAME_BASED_DIRECTORIES` is the one list kept by hand, in `src/manifest.rs` and in `lib/generator/resolvers/api_name_resolver.rb`, and a Ruby test holds the two together. A directory not on it that holds APIs of different names fails generation, by its files.

`src/supplemental.rs` names each schema by its file, as the Ruby generator names its class, with ActiveSupport's `underscore` and Peddler's acronyms: `FBAInventoryAvailabilityChangeNotification.json` is `notifications::fba_inventory_availability_change`. A test checks every name at the pin against the file the Ruby generator wrote.

A name that can't be a Rust module and a Ruby method, or that two files share, fails generation, by the file.

## Models

[Typify](https://github.com/oxidecomputer/typify) writes the models from a model's definitions, after `src/models.rs` has normalized them:

- A number is a `serde_json::Number` with arbitrary precision, so no digit of an amount is lost.
- A string enum stays open: a value Amazon adds later still decodes. An enum whose values are all strings is one, whether or not the model says `type: string`.
- A default is removed, so that a field Amazon didn't send stays absent.

## Pagination

`pagination.json` is the only source of pagination. Nothing is inferred from names when a request runs.

A mapping names the `operation`, the `input` (a JSON pointer to the argument that carries the token) and the `output` (a JSON pointer to the next token in the response). 82 operations are mapped.

A `continuation` may also name another `operation` for the pages after the first.

By default, the request for a next page repeats every argument and replaces the token. A `continuation` changes that:

| Key | Effect on the next request |
| --- | --- |
| `keep` | send only these arguments and the token |
| `drop` | leave these arguments out |
| `set` | set these arguments to fixed values |
| `adapter` | go through an operation of its own, `<operation>.continue`, which sends only the token and the path parameters that are kept. `get_feeds` and `get_reports` need it |

`exclusions` lists 12 operations that look paged and aren't mapped, each with the reason.

Generation checks every mapping against the model, and fails if one doesn't fit.

An operation that takes or returns something that looks like a page token, and that is neither mapped nor excluded, is unmapped. It gets its method in Ruby and Rust, and no `*_pages` one. The generator warns of it, by the spec file and the operation, and the operation inventory lists it under `unmapped_pagination`, so the pull request of a model update shows it. A mapping or an exclusion makes it go from the list.

A mapping or an exclusion of an API Amazon removed is stale: the generator warns of it and sets it aside.
